What is this?

KoldFusion is a web server and CFML engine in about 17,000 lines of dependency-free C. Point a browser at it and you get the whole 1999 experience: <CFQUERY> against a built-in database, session and client variables, <CFMAIL> spooling to real SMTP, scheduled tasks, Verity-style search, WDDX, CFX tags compiled from C, custom tags with ThisTag.GeneratedContent, CFFORM's generated JavaScript… and every page of the navy-and-sage Administrator.

It is not a modern CFML engine. It is the one you remember, bugs and all — variables are case-insensitive, comparisons print YES, nested IIf() still bites, and there are no user-defined functions (those arrived in the next version).

Everything in the Administrator works

server

  • Request limit, timeouts, the Restart at N unresponsive requests watchdog
  • Template & query caching, trusted cache
  • Basic Security: tag restrictions, unsecured tags directory
  • Advanced Security: user directories, contexts, rules, policies
  • Variables, Locking (full checking!), Mappings, Java, Version Info

datasources

  • ODBC, Native Drivers and OLE DB pages
  • "CF Settings >>": restrict SQL operations, login timeout
  • Verify Data Source & a table browser
  • All served by the built-in Flat-File Driver

extensions

  • CFX tags: real shared libraries, ProcessTagRequest()
  • Applets registry for <CFAPPLET>

logging

  • "Severity","ThreadID","Date","Time","Details"
  • Slow-page logging, syslog, mail logging
  • Log file viewer with download & delete

automated tasks

  • One-time, daily/weekly/monthly, every N minutes
  • RUN now, publish output to a static file

miscellaneous

  • Mail: verify, spool, undeliverable folder, respool
  • Debugging output appended to every page
  • Verity collections: create, index, optimize, purge

Authentically insecure

Encrypt() is the original algorithm, re-implemented bit for bit and checked against the published test vector:

<CFOUTPUT>#Encrypt("text", "key")#</CFOUTPUT>   <!--- $38YC!P   --->

It is a three-register bit generator whose key schedule only ever reads characters 5 to 8 of your key. The Administrator stores its own password with it, under a fixed key, in a REGEDIT4-format registry file. As the README says: exactly as insecure as 1999 intended.
