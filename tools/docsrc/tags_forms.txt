# CFML Language Reference: Verity search, Security and Forms tags.
# Sources: src/verity.c, src/security.c, src/tags_form.c.
# CFADMINSECURITY is deliberately not documented: in KoldFusion it always throws
# ("reserved for the KoldFusion Administrator"), so it has no use in a template.

@tag CFCOLLECTION
category: Verity search
summary: Creates, maps, repairs, optimizes or deletes a Verity search collection.
desc:
`CFCOLLECTION` manages Verity collections, the full-text indexes that `CFINDEX` fills and
`CFSEARCH` queries. It does from a template what the Verity page of the KoldFusion Administrator
does by hand, which is handy for setup scripts and for applications that build their own indexes.
syntax:
<CFCOLLECTION ACTION="action"
    COLLECTION="collection_name"
    PATH="directory"
    LANGUAGE="English">
attrs:
ACTION | Required | One of CREATE, MAP, REPAIR, OPTIMIZE or DELETE. See Usage.
COLLECTION | Required | Name of the collection. Letters, digits, underscores and hyphens only.
PATH | Optional; required for MAP | For CREATE, the directory in which the collection's own folder is made. The default is
  the `verity/collections` directory of the KoldFusion installation. For MAP, the directory that already holds the
  collection folder.
LANGUAGE | Optional, default "English" | Recorded with the collection and shown in the Administrator. KoldFusion's search
  engine treats every collection the same way, so the setting is informational.
usage:
- **CREATE** makes a new, empty collection and registers it with the server. It throws an error if a collection
  of that name already exists.
- **MAP** registers a collection that already exists on disk (for example one copied from another server) under
  the given name. Nothing is checked or copied.
- **REPAIR** and **OPTIMIZE** both rewrite the collection file, dropping documents that were deleted. On a
  KoldFusion-sized collection this takes a blink, not the coffee break Verity needed in 1999.
- **DELETE** removes the collection's files and its registration. There is no undo.

Collections are registered under `Verity\Collections` in the server registry and listed on the Verity page of the
Administrator. There is no ACTION="LIST" in 4.5; use the Administrator to see what exists. Errors (unknown
collection, duplicate name, bad characters) throw an exception you can catch with `CFTRY`.
example:
<!--- A throwaway collection: create it, fill it, search it, delete it --->
<CFSET CollName = "snippets_temp">

<!--- tidy up after an interrupted earlier run --->
<CFTRY>
  <CFCOLLECTION ACTION="DELETE" COLLECTION="#CollName#">
<CFCATCH TYPE="Any"></CFCATCH>
</CFTRY>

<CFCOLLECTION ACTION="CREATE" COLLECTION="#CollName#">
<CFINDEX COLLECTION="#CollName#" ACTION="UPDATE" TYPE="PATH"
    KEY="#ExpandPath('/CFDOCS/langref/')#" EXTENSIONS=".htm"
    URLPATH="/CFDOCS/langref">
<CFCOLLECTION ACTION="OPTIMIZE" COLLECTION="#CollName#">
<CFSEARCH NAME="Hits" COLLECTION="#CollName#" CRITERIA="collection" MAXROWS="5">
<CFCOLLECTION ACTION="DELETE" COLLECTION="#CollName#">

<CFOUTPUT>
<H3>Collection #CollName#: created, indexed, searched and deleted</H3>
<P>Language Reference pages that mention "collection" (#Hits.RecordCount# shown):
</CFOUTPUT>
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Score</TH><TH>Page</TH></TR>
<CFOUTPUT QUERY="Hits">
<TR><TD>#Score#</TD><TD><A HREF="#Hits.URL#">#Title#</A></TD></TR>
</CFOUTPUT>
</TABLE>
see: CFINDEX, CFSEARCH, CFTRY

@tag CFINDEX
category: Verity search
summary: Adds documents, files or query rows to a Verity collection, or removes them.
desc:
`CFINDEX` fills a collection with searchable text. It can index the files of a directory, a single
file, or "custom" data: a literal string or every row of a query, which is how you make a database
searchable with `CFSEARCH`.
syntax:
<CFINDEX COLLECTION="collection_name"
    ACTION="action"
    TYPE="type"
    KEY="key"
    TITLE="title"
    BODY="body"
    CUSTOM1="value"
    CUSTOM2="value"
    URLPATH="URL"
    EXTENSIONS="file_extensions"
    QUERY="query_name"
    RECURSE="Yes/No"
    EXTERNAL="Yes/No"
    LANGUAGE="English">
attrs:
COLLECTION | Required | Name of an existing collection (see `CFCOLLECTION`).
ACTION | Required | UPDATE adds documents or replaces those with the same key; DELETE removes documents by key;
  PURGE empties the collection; REFRESH purges and then updates; OPTIMIZE compacts the collection.
TYPE | Optional, default "CUSTOM" | FILE (one file), PATH (the files of a directory) or CUSTOM (text you supply,
  usually query columns).
KEY | Optional | FILE: the full path of the file. PATH: the directory to index. CUSTOM: a unique key for the
  document, or with QUERY the name of the column that holds it (typically the primary key).
TITLE | Optional | CUSTOM only: a literal title, or with QUERY the name of a column. Files get the text of their
  HTML TITLE tag, or the file name.
BODY | Optional | CUSTOM only: the text to index, or with QUERY a comma-separated list of columns whose values are
  joined into the document body.
CUSTOM1 | Optional | A value stored with each document and returned by `CFSEARCH`: a literal, or a query column.
CUSTOM2 | Optional | A second custom value, like CUSTOM1.
URLPATH | Optional | FILE and PATH: URL prefix; the URL column of a search result is URLPATH plus the file's path
  relative to the indexed directory. CUSTOM: stored as given.
EXTENSIONS | Optional, default ".htm, .html, .cfm, .cfml, .txt" | PATH only: comma-separated extensions to index.
  Use "*." for files without an extension.
QUERY | Optional | Name of a query. Each row becomes one document (TYPE="CUSTOM").
RECURSE | Optional, default "No" | PATH only: Yes also indexes subdirectories.
EXTERNAL | Optional | Accepted for compatibility; KoldFusion ignores it.
LANGUAGE | Optional | Accepted for compatibility; KoldFusion ignores it.
usage:
For HTML and CFML files, tags, scripts and style sheets are stripped before the text is indexed, and
the TITLE becomes the document title. With QUERY, KEY, TITLE, BODY, CUSTOM1 and CUSTOM2 name columns;
a name that is not a column is used as literal text.

Indexing happens right away, inside the request. Indexing a large directory on every page view is a
good way to make your 56K visitors wait, so index from an administrative page or a scheduled task
(`CFSCHEDULE`), and use `CFSEARCH` on the public pages.

ACTION="DELETE" works with TYPE="FILE" and TYPE="CUSTOM" (KEY, or KEY plus QUERY). To start over with
a directory, use ACTION="REFRESH".
example:
<!--- Make sure the "snippets" collection exists --->
<CFTRY>
  <CFCOLLECTION ACTION="CREATE" COLLECTION="snippets">
<CFCATCH TYPE="Any"><!--- it already does ---></CFCATCH>
</CFTRY>

<CFQUERY NAME="GetCourses" DATASOURCE="cfsnippets">
SELECT Course_ID, Dept_ID, CorName, CorLevel, CorDesc
FROM CourseList
</CFQUERY>

<!--- One document per row; the key is the primary key --->
<CFINDEX COLLECTION="snippets" ACTION="UPDATE" TYPE="CUSTOM"
    QUERY="GetCourses" KEY="Course_ID" TITLE="CorName"
    BODY="CorName,CorDesc" CUSTOM1="Dept_ID" CUSTOM2="CorLevel">

<CFOUTPUT>
<P>Indexed #GetCourses.RecordCount# courses into the collection <B>snippets</B>.
A few of the documents now in it:
</CFOUTPUT>

<CFSEARCH NAME="Peek" COLLECTION="snippets" CRITERIA="*" MAXROWS="6">
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Key</TH><TH>Title</TH><TH>Custom1</TH><TH>Custom2</TH></TR>
<CFOUTPUT QUERY="Peek">
<TR><TD>#Key#</TD><TD>#Title#</TD><TD>#Custom1#</TD><TD>#Custom2#</TD></TR>
</CFOUTPUT>
</TABLE>
see: CFSEARCH, CFCOLLECTION, CFQUERY, CFSCHEDULE

@tag CFSEARCH
category: Verity search
summary: Searches one or more Verity collections and returns the matches as a query.
desc:
`CFSEARCH` runs a search against collections filled by `CFINDEX` and returns the matching
documents, best first, as a query object you can display with `CFOUTPUT`.
syntax:
<CFSEARCH NAME="search_name"
    COLLECTION="collection_name"
    TYPE="SIMPLE"
    CRITERIA="search_expression"
    MAXROWS="number"
    STARTROW="row_number"
    EXTERNAL="Yes/No"
    LANGUAGE="English">
attrs:
NAME | Required | Name of the query that receives the results.
COLLECTION | Required | One collection, or several separated by commas.
TYPE | Optional, default "SIMPLE" | SIMPLE or EXPLICIT. KoldFusion understands the simple syntax; in explicit
  criteria, operators in angle brackets such as `<NEAR>` are skipped and the remaining words are searched
  with the simple rules.
CRITERIA | Optional | The search expression (see Usage). Empty criteria return no rows.
MAXROWS | Optional, default all | Maximum number of rows to return.
STARTROW | Optional, default "1" | First match to return; use it with MAXROWS to show results a page at a time.
EXTERNAL | Optional | Accepted for compatibility; KoldFusion ignores it.
LANGUAGE | Optional | Accepted for compatibility; KoldFusion ignores it.
usage:
The result query has the columns URL, Key, Title, Score, Custom1, Custom2, Summary and RecordsSearched,
plus the usual RecordCount, CurrentRow and ColumnList. Score runs from 0 to 0.98 relative to the best
match; Summary holds the first 250 characters of the document text.

| Criteria | Finds documents containing |
| `web database` | both words (AND is implied; you may also write it) |
| `web, database` | either word (OR works too) |
| `"safety goggles"` | the exact phrase |
| `chemistry NOT organic` | chemistry but not organic |
| `crypt*` | words matching the wildcard; `?` matches one character |

Matching ignores case, and a trailing "s" still matches (`course` finds "courses"). Words in a title
count three times as much as words in the body.

> Inside `CFOUTPUT`, write `#Results.URL#` rather than `#URL#`: on its own, URL means the URL scope.

If a collection does not exist, `CFSEARCH` throws an error. Pass user input straight to CRITERIA; it is
not SQL, so there is nothing to escape.
example:
<CFPARAM NAME="Form.Criteria" DEFAULT="web">

<!--- Set up the course index (see CFINDEX) so this page stands alone --->
<CFTRY>
  <CFCOLLECTION ACTION="CREATE" COLLECTION="snippets">
<CFCATCH TYPE="Any"></CFCATCH>
</CFTRY>
<CFQUERY NAME="GetCourses" DATASOURCE="cfsnippets">
SELECT Course_ID, Dept_ID, CorName, CorLevel, CorDesc FROM CourseList
</CFQUERY>
<CFINDEX COLLECTION="snippets" ACTION="UPDATE" QUERY="GetCourses"
    KEY="Course_ID" TITLE="CorName" BODY="CorName,CorDesc"
    CUSTOM1="Dept_ID" CUSTOM2="CorLevel">

<CFSEARCH NAME="Results" COLLECTION="snippets"
    CRITERIA="#Form.Criteria#" MAXROWS="10">

<CFOUTPUT>
<FORM ACTION="cfsearch.cfm" METHOD="POST">
Search the course catalog:
<INPUT TYPE="Text" NAME="Criteria" VALUE="#HTMLEditFormat(Form.Criteria)#" SIZE="25">
<INPUT TYPE="Submit" VALUE="Search"><BR>
<FONT SIZE="1">Try: chemistry NOT organic, "safety goggles", crypt*, web, database</FONT>
</FORM>
<P>#Results.RecordCount# match(es) for <B>#HTMLEditFormat(Form.Criteria)#</B>
</CFOUTPUT>
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Score</TH><TH>Course</TH><TH>Dept</TH><TH>Level</TH></TR>
<CFOUTPUT QUERY="Results">
<TR><TD>#Score#</TD><TD>#Title#</TD><TD>#Custom1#</TD><TD>#Custom2#</TD></TR>
</CFOUTPUT>
</TABLE>
see: CFINDEX, CFCOLLECTION, CFOUTPUT, HTMLEditFormat

@tag CFAUTHENTICATE
category: Security
summary: Logs a user in to a security context of Advanced Security.
desc:
`CFAUTHENTICATE` checks a user name and password against the user directories of a security
context. On success the user counts as authenticated for the rest of the request (and, with the
default cookie, for later requests), so `IsAuthenticated`, `AuthenticatedUser` and `IsAuthorized`
can answer questions about them.
syntax:
<CFAUTHENTICATE SECURITYCONTEXT="context"
    USERNAME="user_ID"
    PASSWORD="password"
    SETCOOKIE="Yes/No"
    THROWONFAILURE="Yes/No">
attrs:
SECURITYCONTEXT | Required | A security context defined on the Advanced Security pages of the Administrator.
USERNAME | Required | The user's ID in one of the context's user directories.
PASSWORD | Required | The user's password.
SETCOOKIE | Optional, default "Yes" | Yes sends the cookie CFAUTHORIZATION_context, which keeps the user logged in on
  later requests. With No, the login lasts for the current request only.
THROWONFAILURE | Optional, default "Yes" | Yes throws an exception of TYPE="Security" when the user name or password
  is wrong. With No, check `IsAuthenticated()` or the variable CFAUTHENTICATE.AuthenticationStatus
  ("Success" or "Failure") instead.
usage:
If the security context does not exist, `CFAUTHENTICATE` always throws a Security exception, whatever
THROWONFAILURE says. Catch it with `CFCATCH TYPE="Security"`.

The usual place for the tag is `Application.cfm`: if `IsAuthenticated()` returns No, show a login form;
when the form comes back, call `CFAUTHENTICATE` with the submitted values. Afterwards
`AuthenticatedUser()` and `AuthenticatedContext()` return the user and context, and
`IsAuthorized()` checks the context's rules and policies.

The authorization cookie carries the user, the context and a scrambled (not encrypted) password,
which is checked again on every request; changing a user's password logs them out. Use SSL if the
network between you and your users is not to be trusted.

KoldFusion keeps user directories, contexts, rules and policies in its own registry, managed on the
Advanced Security pages of the Administrator. The tag works whenever the named context exists.
example:
<CFPARAM NAME="Form.UserName" DEFAULT="guest">
<CFPARAM NAME="Form.Password" DEFAULT="guest">

<CFOUTPUT>
<FORM ACTION="cfauthenticate.cfm" METHOD="POST">
User: <INPUT TYPE="Text" NAME="UserName" VALUE="#HTMLEditFormat(Form.UserName)#" SIZE="12">
Password: <INPUT TYPE="Password" NAME="Password" SIZE="12">
<INPUT TYPE="Submit" VALUE="Log in">
</FORM>
</CFOUTPUT>

<!--- The "Snippets" context exists only if an administrator created it --->
<CFTRY>
  <CFAUTHENTICATE SECURITYCONTEXT="Snippets" USERNAME="#Form.UserName#"
      PASSWORD="#Form.Password#" SETCOOKIE="No">
  <CFOUTPUT><P>Welcome, <B>#AuthenticatedUser()#</B>!
  You are logged in to the context #AuthenticatedContext()#.</CFOUTPUT>
<CFCATCH TYPE="Security">
  <CFOUTPUT><P><B>Not logged in:</B> #CFCATCH.Message#<BR>
  <I>#CFCATCH.Detail#</I></CFOUTPUT>
</CFCATCH>
</CFTRY>

<CFOUTPUT><P>IsAuthenticated() returns #IsAuthenticated()#.</CFOUTPUT>
see: CFIMPERSONATE, IsAuthenticated, IsAuthorized, AuthenticatedUser, CFTRY

@tag CFIMPERSONATE
category: Security
summary: Runs a block of code as another user of a security context.
desc:
`CFIMPERSONATE` authenticates a user and runs the code between its start and end tags with that
user's identity, so security checks such as `IsAuthorized` answer for that user. When the end tag is
reached, the previous identity (or none) is restored.
syntax:
<CFIMPERSONATE SECURITYCONTEXT="context"
    USERNAME="user_ID"
    PASSWORD="password"
    TYPE="CF/OS"
    LOGIN="domain">
  code that runs as that user
</CFIMPERSONATE>
attrs:
SECURITYCONTEXT | Required for TYPE="CF" | The security context whose user directories hold the user.
USERNAME | Required | The user to impersonate.
PASSWORD | Required | That user's password.
TYPE | Optional, default "CF" | CF impersonates a user of Advanced Security. OS would impersonate a Windows NT
  account; KoldFusion does not run on NT, so TYPE="OS" always throws an error.
LOGIN | Optional | The NT domain for TYPE="OS". Accepted for compatibility; KoldFusion ignores it.
usage:
If the user name or password is wrong, or the context does not exist, the tag throws an exception of
TYPE="Security" with the message "Impersonation failed." and the body does not run.

Unlike `CFAUTHENTICATE`, `CFIMPERSONATE` sends no cookie and lasts only until its end tag. It is
meant for short stretches of code that need someone else's permissions, such as a page that lets
the help desk run a report on behalf of a user.
example:
<!--- Try both kinds of impersonation and report what happens --->
<TABLE BORDER=1 CELLPADDING=4>
<TR><TH>TYPE</TH><TH>Result</TH></TR>
<CFLOOP LIST="CF,OS" INDEX="ImpType">
  <CFOUTPUT><TR><TD>#ImpType#</TD><TD></CFOUTPUT>
  <CFTRY>
    <CFIMPERSONATE SECURITYCONTEXT="Snippets" USERNAME="reports"
        PASSWORD="reports" TYPE="#ImpType#">
      <CFOUTPUT>Running as #AuthenticatedUser()#.
      May read the reports directory:
      #IsAuthorized("File", "/reports/*", "Read")#</CFOUTPUT>
    </CFIMPERSONATE>
  <CFCATCH TYPE="Security">
    <CFOUTPUT><B>#CFCATCH.Message#</B> #CFCATCH.Detail#</CFOUTPUT>
  </CFCATCH>
  </CFTRY>
  </TD></TR>
</CFLOOP>
</TABLE>
<CFOUTPUT><P>After the end tag, AuthenticatedUser() is "#AuthenticatedUser()#".</CFOUTPUT>
see: CFAUTHENTICATE, IsAuthorized, AuthenticatedUser, CFTRY

@tag CFFORM
category: Forms
summary: Builds an HTML form with automatic JavaScript input validation.
desc:
`CFFORM` writes an HTML FORM tag and collects the validation rules of the `CFINPUT`, `CFSELECT`,
`CFTEXTINPUT` and `CFTREE` controls inside it into a JavaScript function that runs when the user
submits the form. It is also the required container for the Java-style controls `CFGRID`,
`CFTREE`, `CFSLIDER`, `CFTEXTINPUT` and `CFAPPLET`.
syntax:
<CFFORM NAME="name"
    ACTION="form_action"
    METHOD="POST"
    TARGET="window_name"
    ENCTYPE="type"
    ONSUBMIT="javascript"
    PRESERVEDATA="Yes/No"
    ENABLECAB="Yes/No"
    PASSTHROUGH="HTML_attributes">
  form controls
</CFFORM>
attrs:
NAME | Optional | Form name, used in the generated JavaScript. KoldFusion names unnamed forms CFForm_1, CFForm_2...
ACTION | Optional | Page that processes the form. Defaults to the current page.
METHOD | Optional, default "POST" | POST or GET.
TARGET | Optional | Window or frame that receives the response.
ENCTYPE | Optional | Encoding type, for example "multipart/form-data" for file uploads with `CFFILE`.
ONSUBMIT | Optional | JavaScript statement inserted into the generated check function, after the validation
  checks; for example `return confirm('Send it?');`.
PRESERVEDATA | Optional, default "No" | Yes fills the controls with the values submitted to this page instead of their
  VALUE / SELECTED defaults. Works for text fields, `CFTEXTINPUT` and `CFSELECT`.
ENABLECAB | Optional | Offered Internet Explorer users the applet classes as a .cab download. Accepted for
  compatibility; KoldFusion ignores it.
PASSTHROUGH | Optional | Extra HTML attributes copied into the FORM tag as they are.
usage:
`CFFORM` emits a reference to `/CFIDE/scripts/cfform.js` (the validation library), a function
`_CF_checkformname` that tests each rule in turn, and a FORM tag whose onSubmit calls it. When a check
fails, the user sees the control's MESSAGE in an alert box and the field gets the focus. Plain HTML
controls may be mixed freely with the CF ones.

Validation runs in the browser, so a user with JavaScript turned off skips it. For server-side checks
use hidden fields such as `fieldname_required` in an ordinary form, or validate in the action page.

With PRESERVEDATA, radio buttons and check boxes keep their own VALUE and are CHECKED when it matches what
was submitted.

In 1999 the grid, tree, slider and text input controls were Java applets. Browsers dropped Java long
ago, so KoldFusion renders working HTML versions styled after the applets.
example:
<CFIF IsDefined("Form.FieldNames")>
  <H3>You sent:</H3>
  <UL>
  <CFLOOP LIST="#Form.FieldNames#" INDEX="Field">
    <CFOUTPUT><LI>#Field# = #HTMLEditFormat(Evaluate("Form." & Field))#</CFOUTPUT>
  </CFLOOP>
  </UL>
</CFIF>

<CFFORM NAME="Signup" ACTION="cfform.cfm">
<TABLE>
<TR><TD>Name:</TD>
  <TD><CFINPUT TYPE="Text" NAME="FullName" SIZE="25" REQUIRED="Yes"
      MESSAGE="Please tell us your name."></TD></TR>
<TR><TD>Year of birth:</TD>
  <TD><CFINPUT TYPE="Text" NAME="BirthYear" SIZE="4" VALIDATE="integer"
      RANGE="1900,1999" MESSAGE="A year between 1900 and 1999, please."></TD></TR>
<TR><TD>Connection:</TD>
  <TD><CFSELECT NAME="Modem">
      <OPTION>28.8K modem<OPTION SELECTED>56K modem<OPTION>ISDN<OPTION>T1 at work
      </CFSELECT></TD></TR>
</TABLE>
<INPUT TYPE="Submit" VALUE="Sign me up">
</CFFORM>
see: CFINPUT, CFSELECT, CFTEXTINPUT, CFGRID, CFTREE

@tag CFINPUT
category: Forms
summary: Creates a text, password, radio button or check box control with client-side validation.
desc:
`CFINPUT` writes an HTML INPUT control inside a `CFFORM` and registers validation rules for it:
required entry, a data type such as a date or a phone number, a numeric range, or your own
JavaScript function.
syntax:
<CFINPUT TYPE="input_type"
    NAME="name"
    VALUE="initial_value"
    REQUIRED="Yes/No"
    VALIDATE="data_type"
    RANGE="min_value,max_value"
    ONVALIDATE="javascript_function"
    MESSAGE="validation_message"
    ONERROR="javascript_function"
    SIZE="integer"
    MAXLENGTH="integer"
    CHECKED="Yes/No"
    PASSTHROUGH="HTML_attributes">
attrs:
TYPE | Optional, default "Text" | Text, Password, Radio or Checkbox.
NAME | Required | Name of the form field.
VALUE | Optional | Initial value (Text, Password) or the value sent when checked (Radio, Checkbox).
REQUIRED | Optional, default "No" | Yes: the field must not be empty; for radio buttons and check boxes, one of the
  group must be checked.
VALIDATE | Optional | Data type to check: date (mm/dd/yyyy), eurodate (dd/mm/yyyy), time (hh:mm or hh:mm:ss), float,
  integer, telephone (###-###-####), zipcode (##### or #####-####), creditcard (13 to 16 digits with a valid check
  digit) or social_security_number (###-##-####). Empty fields pass unless REQUIRED is set.
RANGE | Optional | Minimum and maximum numeric value, as "min,max". Either may be left out: "0," or ",100".
ONVALIDATE | Optional | Name of your own JavaScript function, called as fn(form, field, value). Return true if the value
  is acceptable.
MESSAGE | Optional | Text of the alert shown when a check fails. The default is "Error in fieldname text."
ONERROR | Optional | Custom error routine. Accepted for compatibility; KoldFusion always uses the standard alert.
SIZE | Optional | Width of the field in characters.
MAXLENGTH | Optional | Maximum number of characters accepted.
CHECKED | Optional, default "No" | Yes pre-selects a radio button or check box.
PASSTHROUGH | Optional | Extra HTML attributes copied into the INPUT tag as they are.
usage:
Each rule becomes a test in the JavaScript function that `CFFORM` generates; the rules are checked in
the order the controls appear, and the first failure stops the submission. All checks happen in the
browser; repeat any check that matters (a credit card, say) in the action page.

The telephone check accepts the common US spellings "617-555-1212", "(617) 555-1212" and
"6175551212". Two-digit years in dates are read as 19xx for 30-99 and 20xx for 00-29, so your forms
will cope with the year 2000.
example:
<CFIF IsDefined("Form.FieldNames")>
  <CFOUTPUT>
  <P><B>Order received:</B> #Form.Quantity# x #Form.Color# case,
  ship #Form.ShipDate# to ZIP #Form.Zip#, phone #Form.Phone#,
  <CFIF IsDefined("Form.GiftWrap")>gift wrapped.<CFELSE>no gift wrap.</CFIF>
  </CFOUTPUT>
</CFIF>

<CFFORM NAME="Order" ACTION="cfinput.cfm">
<TABLE>
<TR><TD>Quantity:</TD><TD><CFINPUT TYPE="Text" NAME="Quantity" VALUE="1" SIZE="3"
    VALIDATE="integer" RANGE="1,99" REQUIRED="Yes"
    MESSAGE="Order between 1 and 99 cases."></TD></TR>
<TR><TD>Case color:</TD><TD>
    <CFINPUT TYPE="Radio" NAME="Color" VALUE="Beige" CHECKED="Yes"> Beige
    <CFINPUT TYPE="Radio" NAME="Color" VALUE="Translucent blue"> Translucent blue</TD></TR>
<TR><TD>Ship on:</TD><TD><CFINPUT TYPE="Text" NAME="ShipDate" SIZE="10" VALIDATE="date"
    VALUE="#DateFormat(DateAdd('d', 7, Now()), 'mm/dd/yyyy')#"
    MESSAGE="Enter the date as mm/dd/yyyy."></TD></TR>
<TR><TD>ZIP code:</TD><TD><CFINPUT TYPE="Text" NAME="Zip" SIZE="10" VALIDATE="zipcode"
    REQUIRED="Yes" MESSAGE="A US ZIP code, like 02139."></TD></TR>
<TR><TD>Phone:</TD><TD><CFINPUT TYPE="Text" NAME="Phone" SIZE="14"
    VALIDATE="telephone" MESSAGE="A phone number like 617-555-1212."></TD></TR>
<TR><TD></TD><TD><CFINPUT TYPE="Checkbox" NAME="GiftWrap" VALUE="Yes"> Gift wrap</TD></TR>
</TABLE>
<INPUT TYPE="Submit" VALUE="Place order">
</CFFORM>
see: CFFORM, CFTEXTINPUT, CFSELECT, IsDefined

@tag CFSELECT
category: Forms
summary: Creates a drop-down list or list box, optionally filled from a query.
desc:
`CFSELECT` writes an HTML SELECT control inside a `CFFORM`. It can build its OPTION list from a
query, pre-select one or more values, and require the user to choose something.
syntax:
<CFSELECT NAME="name"
    SIZE="integer"
    MULTIPLE="Yes/No"
    REQUIRED="Yes/No"
    MESSAGE="text"
    ONERROR="javascript_function"
    QUERY="query_name"
    VALUE="column_name"
    DISPLAY="column_name"
    SELECTED="value_list"
    PASSTHROUGH="HTML_attributes">
  optional OPTION tags
</CFSELECT>
attrs:
NAME | Required | Name of the form field.
SIZE | Optional | Number of visible rows; 1 (the default) gives a drop-down list.
MULTIPLE | Optional, default "No" | Yes lets the user pick several entries; the field then arrives as a
  comma-separated list.
REQUIRED | Optional, default "No" | Yes: the user must pick an entry whose value is not empty.
MESSAGE | Optional | Alert text when REQUIRED fails. Default "Error in fieldname."
ONERROR | Optional | Accepted for compatibility; KoldFusion always uses the standard alert.
QUERY | Optional | Query whose rows become OPTION tags.
VALUE | Required with QUERY | Column that supplies each option's value.
DISPLAY | Optional | Column that supplies the visible text. Defaults to the VALUE column.

@tag CFGRIDUPDATE
category: Forms
summary: Writes the edits made in a CFGRID back to a database table.
desc:
`CFGRIDUPDATE` goes in the action page of a form that contains a `CFGRID` in SELECTMODE="EDIT".
It compares the submitted cells with their original values and runs the matching UPDATE, DELETE and
INSERT statements against one table.
syntax:
<CFGRIDUPDATE GRID="grid_name"
    DATASOURCE="ds_name"
    TABLENAME="table_name"
    KEYONLY="Yes/No"
    DBTYPE="type"
    USERNAME="user"
    PASSWORD="password"
    TABLEOWNER="owner"
    TABLEQUALIFIER="qualifier">
attrs:
GRID | Required | NAME of the `CFGRID` whose data was submitted.
DATASOURCE | Required | Data source that holds the table.
TABLENAME | Required | Table to update. The grid's column names must match the table's column names.
KEYONLY | Optional, default "Yes" | Yes: the WHERE clause of UPDATE and DELETE uses only the table's primary key. No: it
  also requires every other grid column to still hold its original value, so a row someone else changed in the
  meantime is left alone.
DBTYPE | Optional | Accepted for compatibility; KoldFusion ignores it.
USERNAME | Optional | Accepted for compatibility; KoldFusion ignores it.
PASSWORD | Optional | Accepted for compatibility; KoldFusion ignores it.
TABLEOWNER | Optional | Accepted for compatibility; KoldFusion ignores it.
TABLEQUALIFIER | Optional | Accepted for compatibility; KoldFusion ignores it.

The key is the table's PRIMARY KEY column(s); a table without one is keyed on its first column. Include
the key in the grid (hidden with `CFGRIDCOLUMN DISPLAY="No"` or read-only with SELECT="No").

  </CFQUERY>
  <P>After <B>CFGRIDUPDATE</B> the copy holds:
  <TABLE BORDER=1 CELLPADDING=2>
  <CFOUTPUT QUERY="After">
  <TR><TD>#Dept_ID#</TD><TD>#Dept_Name#</TD><TD>#Location#</TD></TR>

`CFTREEITEM`, nested in `CFTREE`, adds one item to the tree, placed under the item named by PARENT.
With QUERY it adds an item for every row instead, and a comma-separated list of columns in VALUE
builds several levels at once (for example departments, then the employees in each).
syntax:
<CFTREEITEM VALUE="text"
    DISPLAY="text"
    PARENT="parent_value"
    IMG="image"
    IMGOPEN="image"
    HREF="URL"
    TARGET="window_name"
    EXPAND="Yes/No"
    QUERY="query_name"
    QUERYASROOT="Yes/No">
attrs:
VALUE | Required | The item's value, which is what gets submitted when it is selected. With QUERY, a column name
  or a comma-separated list of column names, one per tree level.
DISPLAY | Optional | Text shown for the item. Defaults to VALUE. With QUERY, a matching list of columns.
PARENT | Optional | VALUE of the parent item. Leave it out for a top-level item.
IMG | Optional | Icon: folder, document, cd, computer, fixed, floppy or remote, or the URL of a 16x16 image. The
  default is a folder for items with children and a document for the others.
IMGOPEN | Optional | Icon for an expanded folder. Accepted for compatibility; KoldFusion ignores it.
HREF | Optional | Makes the item a link. CFTREEITEMKEY=value is appended to the URL.
TARGET | Optional | Accepted for compatibility; KoldFusion ignores it.
EXPAND | Optional, default "Yes" | No shows the item's children collapsed at first.
QUERY | Optional | Query whose rows become tree items.
QUERYASROOT | Optional | Accepted for compatibility; KoldFusion ignores it.
usage:
Parents must be defined before their children. Items built from a query get a path as their value:
with VALUE="Department,Emp_ID" an employee item's value looks like "/Engineering/12", so use
`ListLast(value, "/")` to get the key. Query-built branches start collapsed unless EXPAND="Yes"; IMG may be
a comma list with one icon per level (otherwise folders and documents are chosen automatically).
example:
<CFIF IsDefined("URL.CFTREEITEMKEY")>
  <CFOUTPUT><P>You clicked the item <B>#HTMLEditFormat(URL.CFTREEITEMKEY)#</B>.</CFOUTPUT>
</CFIF>

<CFFORM NAME="Map" ACTION="cftreeitem.cfm">
<CFTREE NAME="SiteMap" WIDTH="320">
  <CFTREEITEM VALUE="server" DISPLAY="KoldFusion Server 4.5" IMG="computer">
  <CFTREEITEM VALUE="docs" DISPLAY="Documentation" PARENT="server">
  <CFTREEITEM VALUE="langref" DISPLAY="CFML Language Reference"
      PARENT="docs" HREF="cftreeitem.cfm">
  <CFTREEITEM VALUE="snippets" DISPLAY="Examples" PARENT="docs"
      HREF="cftreeitem.cfm">
  <CFTREEITEM VALUE="admin" DISPLAY="Administrator" PARENT="server" EXPAND="No">
  <CFTREEITEM VALUE="datasources" DISPLAY="Data Sources" PARENT="admin"
      IMG="fixed" HREF="cftreeitem.cfm">
  <CFTREEITEM VALUE="verity" DISPLAY="Verity Collections" PARENT="admin"
      IMG="cd" HREF="cftreeitem.cfm">
</CFTREE>
</CFFORM>
testargs: CFTREEITEMKEY=langref
see: CFTREE, CFFORM, ListLast

@tag CFAPPLET
category: Forms
summary: Embeds a Java applet registered in the Administrator into a CFFORM.
desc:
`CFAPPLET` writes the APPLET tag for a Java applet that was registered on the Applets page of the
Administrator, with the registered code location, size and parameter defaults. Attributes on the tag
override the registered values for this one page.
syntax:
<CFAPPLET APPLETSOURCE="applet_name"
    NAME="form_variable_name"
    HEIGHT="pixels"
    WIDTH="pixels"
    VSPACE="pixels"
    HSPACE="pixels"
    ALIGN="alignment"
    NOTSUPPORTED="text"
    param_1="value"
    param_n="value">
attrs:
APPLETSOURCE | Required | Name under which the applet is registered in the Administrator.
NAME | Required | Name of the applet in the page (and of the form field its value would be submitted in).
HEIGHT | Optional | Height in pixels. Defaults to the registered height.
WIDTH | Optional | Width in pixels. Defaults to the registered width.
VSPACE | Optional | Space above and below the applet, in pixels.
HSPACE | Optional | Space to the left and right of the applet, in pixels.
ALIGN | Optional | Left, Right, Top, Middle, Bottom and so on. Defaults to the registered alignment.
NOTSUPPORTED | Optional | HTML shown by browsers that cannot run Java. Defaults to the registered text.
param_n | Optional | Any parameter registered for the applet, by name, overriding its registered default value.
usage:
An unregistered APPLETSOURCE throws an error. KoldFusion ships with two registrations, `copytext` and
`marquee`, and you can add your own on the Applets page.

Today's browsers no longer run Java applets, so what visitors see is the NOTSUPPORTED text. The tag
is kept so that 1999 pages still run; view the page source to admire the generated APPLET tag. The
applet's value is not submitted with the form.
example:
<CFFORM NAME="News" ACTION="cfapplet.cfm">
<P>Today's headline ticker:
<CFAPPLET APPLETSOURCE="marquee" NAME="Ticker" WIDTH="400"
    NOTSUPPORTED="<I>Your browser cannot run Java, so here is the news
    as text: KoldFusion 4.5 ships! Y2K compliance certified!</I>">

<P>An applet that nobody registered:
<CFTRY>
  <CFAPPLET APPLETSOURCE="dancing_hamster" NAME="Hamster">
<CFCATCH TYPE="Any">
  <CFOUTPUT><I>#CFCATCH.Message#</I></CFOUTPUT>
</CFCATCH>
</CFTRY>
</CFFORM>
see: CFFORM, CFOBJECT, CFGRID
