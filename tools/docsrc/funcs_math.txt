# ---------------------------------------------------------------- Mathematical functions

@func Abs
category: Mathematical functions
summary: Returns the absolute value of a number.
desc:
Returns the absolute value of a number, that is, the number without its sign. Positive numbers
and zero come back unchanged; negative numbers come back positive.
syntax:
Abs(number)
params:
number | Any number, or a string that can be converted to one.
returns:
A number greater than or equal to zero.
usage:
Handy for differences where only the size matters, such as "how far off budget are we" or the
number of days between two dates in either order. Use `Sgn` if you need the sign instead.
example:
<CFSET Values = "42,-42,0,-3.75,1999">
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Abs(number)</TH></TR>
<CFLOOP INDEX="n" LIST="#Values#">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#Abs(n)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Sgn, Int, Fix, Round

@func ACos
category: Mathematical functions
summary: Returns the arccosine of a number, in radians.
desc:
Returns the angle, in radians, whose cosine is the given number. The result lies between 0 and
pi (3.14159...).
syntax:
ACos(number)
params:
number | The cosine of the angle: a number between -1 and 1 inclusive.
returns:
The angle in radians, from 0 to `Pi()`.
usage:
A value outside the range -1 to 1 raises an Expression error ("Parameter validation error for
function ACOS"). To convert the result to degrees, multiply by 180 and divide by `Pi`.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>ACos (radians)</TH><TH>degrees</TH></TR>
<CFLOOP INDEX="n" LIST="1,0.5,0,-0.5,-1">
<CFSET r = ACos(n)>
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD>#NumberFormat(r, "9.9999")#</TD>
<TD ALIGN="RIGHT">#Round(r * 180 / Pi())#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Cos, ASin, Atn, Pi

@func ASin
category: Mathematical functions
summary: Returns the arcsine of a number, in radians.
desc:
Returns the angle, in radians, whose sine is the given number. The result lies between -pi/2 and
pi/2.
syntax:
ASin(number)
params:
number | The sine of the angle: a number between -1 and 1 inclusive.
returns:
The angle in radians, from `-Pi()/2` to `Pi()/2`.
usage:
A value outside the range -1 to 1 raises an Expression error. Multiply the result by
`180 / Pi()` to get degrees.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>ASin (radians)</TH><TH>degrees</TH></TR>
<CFLOOP INDEX="n" LIST="-1,-0.5,0,0.5,1">
<CFSET r = ASin(n)>
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD>#NumberFormat(r, "9.9999")#</TD>
<TD ALIGN="RIGHT">#Round(r * 180 / Pi())#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Sin, ACos, Atn, Pi

@func Atn
category: Mathematical functions
summary: Returns the arctangent of a number, in radians.
desc:
Returns the angle, in radians, whose tangent is the given number. The result lies between -pi/2
and pi/2. Any number is accepted.
syntax:
Atn(number)
params:
number | The tangent of the angle; any number.
returns:
The angle in radians, strictly between `-Pi()/2` and `Pi()/2`.
usage:
A classic trick: `4 * Atn(1)` is pi, which is how programmers got pi before there was a `Pi`
function. KoldFusion has no two-argument arctangent; divide y by x yourself and mind the quadrant.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Atn (radians)</TH><TH>degrees</TH></TR>
<CFLOOP INDEX="n" LIST="-1000,-1,0,1,1000">
<CFSET r = Atn(n)>
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD>#NumberFormat(r, "9.9999")#</TD>
<TD ALIGN="RIGHT">#NumberFormat(r * 180 / Pi(), "99.99")#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
<CFOUTPUT><P>4 * Atn(1) = #4 * Atn(1)#</CFOUTPUT>
see: Tan, ASin, ACos, Pi

@func BitAnd
category: Mathematical functions
summary: Performs a bitwise logical AND of two integers.
desc:
Returns the bitwise AND of two integers: each bit of the result is 1 only if the same bit is 1
in both arguments. Fractional parts are discarded before the operation.
syntax:
BitAnd(number1, number2)
params:
number1 | An integer.
number2 | An integer.
returns:
An integer.
usage:
The usual job of `BitAnd` is testing flags packed into one number: `BitAnd(Flags, 4) NEQ 0` is
true when bit 2 is set. To read several adjacent bits at once, `BitMaskRead` is more readable.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>a</TH><TH>b</TH><TH>a (binary)</TH><TH>b (binary)</TH><TH>BitAnd(a, b)</TH></TR>
<CFLOOP INDEX="pair" LIST="12:10,255:15,6:9,1999:2000">
<CFSET a = ListFirst(pair, ":")><CFSET b = ListLast(pair, ":")>
<CFOUTPUT><TR><TD>#a#</TD><TD>#b#</TD><TD><TT>#FormatBaseN(a, 2)#</TT></TD>
<TD><TT>#FormatBaseN(b, 2)#</TT></TD><TD><B>#BitAnd(a, b)#</B> (<TT>#FormatBaseN(BitAnd(a, b), 2)#</TT>)</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: BitOr, BitXor, BitNot, BitMaskRead

@func BitMaskClear
category: Mathematical functions
summary: Clears a run of bits in an integer.
desc:
Returns the number with `length` bits, starting at bit `start` (bit 0 is the lowest), set to zero.
All other bits are left alone.
syntax:
BitMaskClear(number, start, length)
params:
number | A 32-bit integer.
start | Position of the lowest bit to clear, 0 to 31.
length | Number of bits to clear, 1 to 31.
returns:
An integer.
usage:
`BitMaskClear(n, s, l)` is shorthand for `BitAnd(n, BitNot(BitSHLN(2^l - 1, s)))`. The result is
a signed 32-bit integer, so clearing bits of a negative number may still give a negative number.
example:
<CFSET n = 255>
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Call</TH><TH>Result</TH><TH>Binary</TH></TR>
<CFLOOP INDEX="args" LIST="0:4,4:4,2:3,7:1">
<CFSET s = ListFirst(args, ":")><CFSET l = ListLast(args, ":")>
<CFSET r = BitMaskClear(n, s, l)>
<CFOUTPUT><TR><TD><TT>BitMaskClear(#n#, #s#, #l#)</TT></TD><TD ALIGN="RIGHT">#r#</TD>
<TD><TT>#Right("00000000" & FormatBaseN(r, 2), 8)#</TT></TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: BitMaskSet, BitMaskRead, BitAnd, BitNot

@func BitMaskRead
category: Mathematical functions
summary: Reads a run of bits from an integer.
desc:
Extracts `length` bits from the number, starting at bit `start` (bit 0 is the lowest), and returns
them as an integer shifted down to bit 0.
syntax:
BitMaskRead(number, start, length)
params:
number | A 32-bit integer.
start | Position of the lowest bit to read, 0 to 31.
length | Number of bits to read, 1 to 31.
returns:
A non-negative integer between 0 and 2^length - 1.
usage:
Useful for unpacking several small values stored in one integer column, a favorite space-saving
trick from the days when a 1 GB disk was big. `BitMaskSet` packs them in again.
example:
<!--- Pack a date into one integer: day in bits 0-4, month in bits 5-8, year offset in bits 9-15 --->
<CFSET Packed = 31 + 12 * 32 + 99 * 512>
<CFOUTPUT>
<P>Packed value: #Packed# (binary <TT>#FormatBaseN(Packed, 2)#</TT>)
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Field</TH><TH>Call</TH><TH>Value</TH></TR>
<TR><TD>Day</TD><TD><TT>BitMaskRead(Packed, 0, 5)</TT></TD><TD>#BitMaskRead(Packed, 0, 5)#</TD></TR>
<TR><TD>Month</TD><TD><TT>BitMaskRead(Packed, 5, 4)</TT></TD><TD>#BitMaskRead(Packed, 5, 4)#</TD></TR>
<TR><TD>Year - 1900</TD><TD><TT>BitMaskRead(Packed, 9, 7)</TT></TD><TD>#BitMaskRead(Packed, 9, 7)#</TD></TR>
</TABLE>
</CFOUTPUT>
see: BitMaskSet, BitMaskClear, BitAnd, BitSHRN

@func BitMaskSet
category: Mathematical functions
summary: Writes a value into a run of bits of an integer.
desc:
Returns the number with `length` bits, starting at bit `start`, replaced by the low bits of `mask`.
Bits outside that run are left alone.
syntax:
BitMaskSet(number, mask, start, length)
params:
number | A 32-bit integer to modify.
mask | The value to store. Only its lowest `length` bits are used.
start | Position of the lowest bit to write, 0 to 31.
length | Number of bits to write, 1 to 31.
returns:
An integer (signed 32-bit).
usage:
Think of it as `BitMaskClear` followed by a `BitOr` of the mask shifted into place. If the mask
is too large for the field, the extra high bits are silently dropped.
example:
<CFSET Packed = 0>
<CFSET Packed = BitMaskSet(Packed, 31, 0, 5)>   <!--- day   --->
<CFSET Packed = BitMaskSet(Packed, 12, 5, 4)>   <!--- month --->
<CFSET Packed = BitMaskSet(Packed, 99, 9, 7)>   <!--- year - 1900 --->
<CFOUTPUT>
<P>Packed date: #Packed# (binary <TT>#FormatBaseN(Packed, 2)#</TT>)
<P>Unpacked: #BitMaskRead(Packed, 5, 4)#/#BitMaskRead(Packed, 0, 5)#/#1900 + BitMaskRead(Packed, 9, 7)#
<P>Too big for the field: <TT>BitMaskSet(0, 255, 4, 3)</TT> = #BitMaskSet(0, 255, 4, 3)#
(only 3 bits, <TT>111</TT>, were stored)
</CFOUTPUT>
see: BitMaskRead, BitMaskClear, BitOr, BitSHLN

@func BitNot
category: Mathematical functions
summary: Performs a bitwise logical NOT (one's complement) of an integer.
desc:
Returns the one's complement of a 32-bit integer: every 0 bit becomes 1 and every 1 bit becomes 0.
syntax:
BitNot(number)
params:
number | A 32-bit integer.
returns:
A signed 32-bit integer. For any n, `BitNot(n)` equals `-n - 1`.
usage:
Because the result is signed, `BitNot(0)` is -1 (all 32 bits set). Combine with `BitAnd` to turn
flags off: `BitAnd(Flags, BitNot(4))` clears bit 2.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>BitNot(number)</TH><TH>BitAnd(255, BitNot(number))</TH></TR>
<CFLOOP INDEX="n" LIST="0,1,12,255,-1">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#BitNot(n)#</TD>
<TD ALIGN="RIGHT">#BitAnd(255, BitNot(n))#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: BitAnd, BitOr, BitXor, BitMaskClear

@func BitOr
category: Mathematical functions
summary: Performs a bitwise logical OR of two integers.
desc:
Returns the bitwise OR of two integers: each bit of the result is 1 if the same bit is 1 in
either argument (or both).
syntax:
BitOr(number1, number2)
params:
number1 | An integer.
number2 | An integer.
returns:
An integer.
usage:
Use `BitOr` to switch flags on: `Flags = BitOr(Flags, 8)` sets bit 3 and leaves the rest as they
were. Setting a flag that is already on does no harm.
example:
<CFSET Read = 1><CFSET Write = 2><CFSET Delete = 4>
<CFSET Rights = 0>
<CFSET Rights = BitOr(Rights, Read)>
<CFSET Rights = BitOr(Rights, Write)>
<CFSET Rights = BitOr(Rights, Write)>  <!--- twice is harmless --->
<CFOUTPUT>
<P>Rights = #Rights# (binary <TT>#FormatBaseN(Rights, 2)#</TT>)
<UL>
<LI>Read: #YesNoFormat(BitAnd(Rights, Read))#
<LI>Write: #YesNoFormat(BitAnd(Rights, Write))#
<LI>Delete: #YesNoFormat(BitAnd(Rights, Delete))#
</UL>
<P>BitOr(12, 10) = #BitOr(12, 10)#
</CFOUTPUT>
see: BitAnd, BitXor, BitNot, BitMaskSet

@func BitSHLN
category: Mathematical functions
summary: Shifts the bits of an integer to the left.
desc:
Shifts a 32-bit integer `count` bits to the left. Zeros come in from the right and bits shifted
past bit 31 are lost.
syntax:
BitSHLN(number, count)
params:
number | A 32-bit integer.
count | Number of positions to shift, 0 to 31.
returns:
A signed 32-bit integer.
usage:
Shifting left by n multiplies by 2^n as long as nothing falls off the top. Shifting a 1 into bit
31 gives a negative number (-2147483648), because the result is signed.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>count</TH><TH>BitSHLN(number, count)</TH></TR>
<CFLOOP INDEX="args" LIST="1:0,1:4,3:8,255:8,1:31">
<CFSET n = ListFirst(args, ":")><CFSET c = ListLast(args, ":")>
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#c#</TD>
<TD ALIGN="RIGHT">#BitSHLN(n, c)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: BitSHRN, BitMaskSet, BitAnd

@func BitSHRN
category: Mathematical functions
summary: Shifts the bits of an integer to the right.
desc:
Shifts a 32-bit integer `count` bits to the right. Bits shifted past bit 0 are lost and zeros
come in from the left (an unsigned, or logical, shift).
syntax:
BitSHRN(number, count)
params:
number | A 32-bit integer.
count | Number of positions to shift, 0 to 31.
returns:
A non-negative integer.
usage:
For positive numbers, shifting right by n is the same as `Int(number / 2^n)`. Because zeros come
in from the left, a negative number becomes a large positive one: `BitSHRN(-1, 28)` is 15.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>count</TH><TH>BitSHRN(number, count)</TH></TR>
<CFLOOP INDEX="args" LIST="256:4,255:4,65535:8,1999:1,-1:28">
<CFSET n = ListFirst(args, ":")><CFSET c = ListLast(args, ":")>
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#c#</TD>
<TD ALIGN="RIGHT">#BitSHRN(n, c)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: BitSHLN, BitMaskRead, BitAnd

@func BitXor
category: Mathematical functions
summary: Performs a bitwise logical exclusive OR of two integers.
desc:
Returns the bitwise exclusive OR of two integers: each bit of the result is 1 if the same bit is
1 in exactly one of the arguments.
syntax:
BitXor(number1, number2)
params:
number1 | An integer.
number2 | An integer.
returns:
An integer.
usage:
XOR toggles bits: `BitXor(Flags, 4)` flips bit 2 on if it was off, and off if it was on. Applying
the same XOR twice gives back the original number, which made it the "encryption" of choice for
many a shareware program.
example:
<CFSET Secret = 1999><CFSET Key = 1234>
<CFSET Scrambled = BitXor(Secret, Key)>
<CFOUTPUT>
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Value</TH><TH>Decimal</TH><TH>Binary</TH></TR>
<TR><TD>Secret</TD><TD ALIGN="RIGHT">#Secret#</TD><TD><TT>#FormatBaseN(Secret, 2)#</TT></TD></TR>
<TR><TD>Key</TD><TD ALIGN="RIGHT">#Key#</TD><TD><TT>#FormatBaseN(Key, 2)#</TT></TD></TR>
<TR><TD>BitXor(Secret, Key)</TD><TD ALIGN="RIGHT">#Scrambled#</TD><TD><TT>#FormatBaseN(Scrambled, 2)#</TT></TD></TR>
<TR><TD>BitXor(that, Key)</TD><TD ALIGN="RIGHT">#BitXor(Scrambled, Key)#</TD><TD><TT>#FormatBaseN(BitXor(Scrambled, Key), 2)#</TT></TD></TR>
</TABLE>
</CFOUTPUT>
see: BitAnd, BitOr, BitNot

@func Ceiling
category: Mathematical functions
summary: Returns the smallest integer greater than or equal to a number.
desc:
Rounds a number up to the next whole number. Integers come back unchanged.
syntax:
Ceiling(number)
params:
number | Any number.
returns:
An integer.
usage:
"Up" means toward positive infinity, so `Ceiling(-3.7)` is -3. Its counterpart, which rounds down,
is `Int`. A common use is counting pages: `Ceiling(RecordCount / 10)` pages of 10 rows.
example:
<CFQUERY NAME="GetParks" DATASOURCE="cfsnippets">
SELECT ParkName FROM Parks
</CFQUERY>
<CFOUTPUT>
<P>#GetParks.RecordCount# parks at 10 per page need #Ceiling(GetParks.RecordCount / 10)# pages.
</CFOUTPUT>
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Ceiling</TH><TH>Int</TH></TR>
<CFLOOP INDEX="n" LIST="3.2,3.7,3,-3.2,-3.7">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#Ceiling(n)#</TD><TD ALIGN="RIGHT">#Int(n)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Int, Fix, Round

@func Cos
category: Mathematical functions
summary: Returns the cosine of an angle given in radians.
desc:
Returns the cosine of an angle. The angle must be in radians; to convert degrees, multiply by
`Pi()` and divide by 180.
syntax:
Cos(number)
params:
number | An angle in radians.
returns:
A number between -1 and 1.
usage:
Floating-point arithmetic is not exact: `Cos(Pi()/2)` gives a tiny number such as 6.12E-017
rather than a clean zero. Format results with `NumberFormat` or `Round` before showing them.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>Degrees</TH><TH>Cos</TH></TR>
<CFLOOP INDEX="deg" LIST="0,30,45,60,90,180">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#deg#</TD><TD>#NumberFormat(Cos(deg * Pi() / 180), "9.9999")#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Sin, Tan, ACos, Pi

@func DecrementValue
category: Mathematical functions
summary: Returns the integer part of a number, decreased by one.
desc:
Drops the fractional part of a number and subtracts one.
syntax:
DecrementValue(number)
params:
number | Any number.
returns:
An integer.
usage:
`DecrementValue(17.5)` is 16, not 16.5. If you want to keep the fraction, just write `n - 1`.
`IncrementValue` goes the other way.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>DecrementValue(number)</TH><TH>number - 1</TH></TR>
<CFLOOP INDEX="n" LIST="10,17.5,1,0.25">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#DecrementValue(n)#</TD><TD ALIGN="RIGHT">#n - 1#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
<P>Countdown:
<CFSET n = 5>
<CFLOOP CONDITION="n GT 0"><CFOUTPUT>#n#... </CFOUTPUT><CFSET n = DecrementValue(n)></CFLOOP>
Happy New Year!
see: IncrementValue, Int, Fix

@func Exp
category: Mathematical functions
summary: Returns e raised to a power.
desc:
Returns the constant e (2.71828182846, the base of natural logarithms) raised to the given power.
syntax:
Exp(number)
params:
number | The exponent.
returns:
A positive number.
usage:
`Exp` is the inverse of `Log`: `Log(Exp(x))` is x. For other bases use the `^` operator, for
example `2^10`. Compound interest calculated continuously is `Principal * Exp(Rate * Years)`.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Exp(number)</TH></TR>
<CFLOOP INDEX="n" LIST="0,1,2,-1,10">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD>#Exp(n)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
<CFOUTPUT>
<P>$1,000 at 5% compounded continuously for 10 years:
#DollarFormat(1000 * Exp(0.05 * 10))#
</CFOUTPUT>
see: Log, Log10, Sqr

@func Fix
category: Mathematical functions
summary: Removes the fractional part of a number, rounding toward zero.
desc:
Returns the integer part of a number by simply cutting off everything after the decimal point.
syntax:
Fix(number)
params:
number | Any number.
returns:
An integer.
usage:
For positive numbers `Fix` and `Int` agree. For negative numbers they differ: `Fix(-3.7)` is -3
(toward zero) while `Int(-3.7)` is -4 (down).
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Fix</TH><TH>Int</TH><TH>Round</TH><TH>Ceiling</TH></TR>
<CFLOOP INDEX="n" LIST="3.7,3.2,-3.2,-3.7">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT"><B>#Fix(n)#</B></TD><TD ALIGN="RIGHT">#Int(n)#</TD>
<TD ALIGN="RIGHT">#Round(n)#</TD><TD ALIGN="RIGHT">#Ceiling(n)#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
see: Int, Round, Ceiling

@func FormatBaseN
category: Mathematical functions
summary: Converts a number to a string in a given base (radix).
desc:
Converts a number to its representation in base 2 through 36. Digits beyond 9 are written as
lowercase letters (a = 10, b = 11, ... z = 35).
syntax:
FormatBaseN(number, radix)
params:
number | The number to convert. Any fractional part is discarded.
radix | The base, from 2 to 36.
returns:
A string. Negative numbers get a leading minus sign.
usage:
A radix outside 2-36 raises an Expression error. Use `InputBaseN` to convert back to decimal.
Base 16 is useful for HTML colors: `Right("0" & FormatBaseN(n, 16), 2)` gives two hex digits.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>Base 2</TH><TH>Base 8</TH><TH>Base 16</TH><TH>Base 36</TH></TR>
<CFLOOP INDEX="n" LIST="10,255,1999,-42">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD><TT>#FormatBaseN(n, 2)#</TT></TD><TD><TT>#FormatBaseN(n, 8)#</TT></TD>
<TD><TT>#FormatBaseN(n, 16)#</TT></TD><TD><TT>#FormatBaseN(n, 36)#</TT></TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
<P>A web-safe palette row:
<CFLOOP INDEX="g" FROM="0" TO="255" STEP="51">
<CFSET hex = Right("0" & FormatBaseN(g, 16), 2)>
<CFOUTPUT><FONT COLOR="##00#hex#00"><B>##00#hex#00</B></FONT> </CFOUTPUT>
</CFLOOP>
see: InputBaseN, NumberFormat, BitAnd

@func IncrementValue
category: Mathematical functions
summary: Returns the integer part of a number, increased by one.
desc:
Drops the fractional part of a number and adds one.
syntax:
IncrementValue(number)
params:
number | Any number.
returns:
An integer.
usage:
`IncrementValue(17.5)` is 18, not 18.5. It is commonly used for counters, though `n + 1` does the
same job for whole numbers. `DecrementValue` goes the other way.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>number</TH><TH>IncrementValue(number)</TH><TH>number + 1</TH></TR>
<CFLOOP INDEX="n" LIST="10,17.5,0,1998.9">
<CFOUTPUT><TR><TD ALIGN="RIGHT">#n#</TD><TD ALIGN="RIGHT">#IncrementValue(n)#</TD><TD ALIGN="RIGHT">#n + 1#</TD></TR></CFOUTPUT>
</CFLOOP>
</TABLE>
<CFSET Visitors = 0>
<CFLOOP INDEX="i" FROM="1" TO="3"><CFSET Visitors = IncrementValue(Visitors)></CFLOOP>
<CFOUTPUT><P>You are visitor number #Visitors#!</CFOUTPUT>
see: DecrementValue, Int, Fix

@func InputBaseN
category: Mathematical functions
summary: Converts a string in a given base (radix) to a decimal integer.
desc:
Reads a string as a number written in base 2 through 36 and returns its decimal value. Letters
may be upper or lower case.
syntax:
InputBaseN(string, radix)
params:
string | The digits of the number, optionally with a leading minus sign, for example "FF" or "1010".
radix | The base the string is written in, from 2 to 36.
returns:
An integer.
usage:
A string containing a digit that is not valid in the radix (such as "12G" in base 16), or an empty
string, raises an Expression error. Wrap user input in `CFTRY` or check it first.
`FormatBaseN` converts the other way.
example:
<TABLE BORDER=1 CELLPADDING=3>
<TR><TH>string</TH><TH>radix</TH><TH>InputBaseN</TH></TR>
<CFLOOP INDEX="args" LIST="1010:2,777:8,FF:16,cafe:16,ZZ:36">

@func IsSimpleValue
category: Decision functions
summary: Determines whether a value is a simple value (string, number, Boolean or date).
desc:
Returns YES for simple values: strings, numbers, Booleans and date/time values. Returns NO for

IsSimpleValue(value)

value | Any value.

YES or NO.

@func IsWDDX
category: Decision functions
summary: Determines whether a string is a WDDX packet.
desc:
Returns YES if the value is a string containing a WDDX packet, such as one produced by
`CFWDDX ACTION="CFML2WDDX"`.
syntax:
IsWDDX(value)
params:
value | Any value, usually a string received from another server or a form field.
returns:
YES or NO.
usage:

</CFOUTPUT>
